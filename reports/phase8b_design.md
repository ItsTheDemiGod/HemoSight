# Phase 8B - visual redesign

Generated by `scripts/design_review_report_phase8b.py` from `data/interim/phase8b/`. Direction: the atmosphere of a dark, typographic, parallax landing page translated to this project's subject - a precision instrument, not a document. Language (Phase 8A) unchanged.

## 3. Motion inventory

GSAP 3.15 + ScrollTrigger for scroll-driven sequences, loaded lazily and only when motion is on (two chunks, 28 + 18 kB gzipped, never fetched otherwise); Framer Motion keeps component state transitions. One switch governs everything decorative: `enabled = !prefers-reduced-motion && userToggle`, stamped on `<html data-motion>`.

| effect | implementation | off when motion is off |
| --- | --- | --- |
| scrollytelling (landing) | visual pinned at md+ via `gsap.matchMedia`, five steps set the active figure on enter; crossfade is opacity only; on phones each step carries its own figure, nothing pins | static: steps in order, each with its figure, same numbers |
| parallax | three hero layers scrubbed at -60 / -120 / -30 px, transform only | layers static |
| reveal on scroll | `.reveal` elements animate in with a 0.08 s stagger; the class hides nothing unless `data-motion=on` | everything visible at load |
| particle field | canvas, <= 70 points at 6 px/s, draws only while intersecting and the tab is visible | component renders nothing |
| glowing borders | conic-gradient pseudo-element rotated by a registered `--glow-angle` property on hover/focus-within; card lifts 2 px by transform | hover lift off; no sweep |
| hover states | buttons swap fill/outline with a glow shadow; links draw an underline from the left | instant |
| custom cursor | reticle following the pointer, opens near interactive elements; fine pointers only; hides on any keydown so it never covers a focus ring; native cursor hidden only while it is live | not rendered; native cursor |
| page transitions | Framer Motion fade/6 px rise | duration forced to ~0 by CSS |

Everything animates transform or opacity. Scroll handling is GSAP's frame-throttled listener; the particle loop is `requestAnimationFrame` and stops off-screen.

## 4. Accessibility and performance, measured

Lighthouse 13.4, headless Chrome, `vite preview` build with the backend running. Mobile is Lighthouse's default emulation (the harder profile); desktop is `--preset=desktop`.

| page | preset | performance | accessibility | best practices | LCP | TBT | CLS |
| --- | --- | --- | --- | --- | --- | --- | --- |
| landing, BEFORE 8B (cream palette) | mobile | 99 | 95 | 96 | 1.6 s | 100 ms | 0 |
| landing | mobile | **97** | **100** | 100 | 2.1 s | 160 ms | 0 |
| landing | desktop | **100** | **100** | 100 | 0.6 s | 20 ms | 0 |
| upload | mobile | **99** | **100** | 100 | 1.6 s | 70 ms | 0 |
| upload | desktop | **100** | **100** | 100 | 0.4 s | 0 ms | 0 |
| results (real run, 7 checks) | mobile | **99** | **100** | 100 | 1.7 s | 70 ms | 0 |
| results (real run, 7 checks) | desktop | **100** | **100** | 100 | 0.4 s | 0 ms | 0 |

The bar was performance 90 and accessibility 97. The baseline landing page lost accessibility points to **18 colour-contrast failures** on the cream palette; the new palette clears every text pair and every page scores 100.

**Bundle.** Before: one JS chunk 336.6 kB (107.5 kB gzipped) + CSS 16.2 kB. After: main chunk 366 kB (118.4 kB gzipped) + CSS 20.7 kB (5.3 kB gzipped), plus two lazy chunks that load only with motion on - GSAP core 70.8 kB (28.0 kB gzipped) and ScrollTrigger 44.0 kB (18.3 kB gzipped). A reduced-motion visitor downloads about 11 kB gzipped more than before; a motion-on visitor about 57 kB more.

**Cut to hold the bar, or corrected during verification:**
- Lazy-loading the landing page itself (17 kB) was reverted: it cost a layout shift on first paint (CLS 0.12). Only GSAP is code-split now.
- Inactive story steps were dimmed to 35% opacity; Lighthouse flagged the dimmed text below AA. The dim is now 75% minimum, applied to the body only, never to labels.
- The results page replaced an empty state with the verdict cards after its fetch and pushed the page foot down (CLS 0.73 on desktop). It now shows a loading state and the content column is at least one viewport tall; CLS 0.
- Two `bg-white` fragments from the old palette survived in the results and report pages (Lighthouse: white select on dark ground); replaced by tokens, and a test now forbids any hex colour outside `tokens.css`.
- The hero spectra sat under the heading on phones; it is now a quieter top-right layer at small widths, and the visible-band gradient beneath the curves was halved.
- Nothing was cut for performance: the particle field, parallax, scrollytelling and glow borders all ship, because the measured scores stayed above the bar with them.

## 5. Verification - what was actually checked

`tools/verify_8b.mjs` drove headless Chrome through **every page x three widths (1440, 834, 390) x two motion modes** (motion on; `prefers-reduced-motion: reduce` emulated) = 48 page states, scrolling each like a reader and recording console errors, `html[data-motion]` and `[data-cursor]`, whether every `.reveal` element ended visible, horizontal overflow, and whether the first Tab lands on a focusable element with a visible outline. **48 of 48 clean.** Screenshots in `data/interim/phase8b/shots/`.

Read: with reduced motion emulated, `data-motion` is `off`, the cursor is `native`, no canvas exists, every reveal element is visible without scrolling, and the first Tab shows a focus ring on the skip link - on every page at every width. With motion on, the particle canvas exists only on the landing page, reveals complete on scroll, and the custom cursor stays `native` until a mouse moves (headless has no pointer).

Verified by eye from the screenshots: the results page's verdict cards read as findings (calm, labelled, glyph + hue + text; plain and technical layers intact); the mobile hero no longer overlaps the heading; the story steps on phones carry their own figures. The in-app motion toggle was exercised by test only through its attribute effect, not by a recorded click.

## 6. Restraint

Verdict cards use no glow animation beyond the shared hover lift; numbers, p-values and technical statements are set in the monospace on a flat surface with no decoration; the disclaimer is in the sidebar frame of every page (and the top bar on phones) beside the motion toggle, not in a footer. Motion directs attention to the section entering view and never runs over text being read: reveals fire once and stop; the story pin holds the figure still while the text scrolls.
